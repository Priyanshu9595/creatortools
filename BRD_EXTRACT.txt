1. Executive Summary and Business Goals
Product vision
Build a private single-creator workspace where the owner can create a project, use one or more production tools, edit generated output, save versions, manage personal media, and export or publish the result. The application uses one creator dashboard and does not include an admin dashboard, organizations, teams, subscriptions, billing, or user-management features.
Business problem
Creators use disconnected tools for ideation, transcription, podcast publishing, thumbnail design, and ad planning.
Manual file movement and repeated data entry increase production time and cause version confusion.
Many creator tools become unusable when free trials expire or require expensive media-processing APIs.
Small creators need guided workflows, not only blank editors or generic chat responses.
Business objectives
Objective
MVP outcome / indicator
Unified personal workflow
The creator accesses all five modules from one secured dashboard.
Faster creation
Generate a first editable output within 60 seconds for text tasks.
Reliable media handling
Uploads show progress, processing status, retry, and clear failure messages.
Zero-cost development path
Core flows use free tiers or open-source/self-hosted processing.
Reusable project history
Every output is linked to a personal project, version, source asset, and export.
Quota protection
Local daily limits and provider fallbacks protect free API allowances.
Suggested MVP KPIs
Successful generation rate >= 95% for valid text requests.
Successful transcription job completion >= 90% for supported files.
RSS validation pass rate = 100% before feed activation.
At least 80% of user projects can be reopened and edited without data loss.
Average dashboard API response under 2 seconds, excluding background jobs.

The creator opens the secured application and completes personal profile or brand settings.
The creator creates a project from the single dashboard and selects Script, Subtitle, Podcast, Thumbnail, or Storyboard.

The application displays progress and saves intermediate state to prevent data loss.

5. Architecture and Free API Strategy
Recommended logical architecture
Use a React/Next.js frontend, Node.js API layer, PostgreSQL or MongoDB, object storage, Redis-backed job queue where available, and separate workers for FFmpeg or transcription. All provider calls pass through backend adapters; secret keys must never be exposed to the browser.

7. Module 2 - Subtitle and Caption Generator
Purpose and workflow
Convert uploaded audio/video into editable time-coded captions, then export subtitle files or optionally render captions into video. Processing must run as a background job for media longer than a small synchronous threshold.
1. Validate file type, size, duration, and personal quota.
2. Upload original media to object storage.
3. Use FFmpeg to extract/compress 16 kHz mono audio and split large files.
4. Transcribe chunks with Groq Whisper or self-hosted Faster-Whisper.
5. Merge timestamps, normalize punctuation, and save editable segments.
6. Export SRT, VTT, TXT, or queue a captioned-video render.
Functional requirements
ID
Requirement
SC-01
Support MP4, MOV, WebM, MP3, WAV, and M4A within configured limits.
SC-02
Display upload and processing progress with retry and failure reason.
SC-03
Provide segment-level text and timestamp editing.
SC-04
Support language detection, manual language override, and optional translation.
SC-05
Generate valid SRT and WebVTT with monotonic timestamps.
SC-06
Preserve corrected segments during reprocessing where segment mapping is possible.
SC-07
Allow caption style selection before rendering a captioned video.
Free API recommendation
Groq Whisper + FFmpeg
Groq provides fast transcription during MVP; Faster-Whisper is the no-per-request fallback. FFmpeg reduces file size, splits long audio, and renders subtitle overlays. Never send full large video files directly to the transcription API.

9. Module 3 - Episode Lifecycle, Storage, and AI

2. Upload MP3/M4A/WAV/AAC; validate MIME type, size, and media integrity.

10. Module 3 - RSS Publisher
How publishing works
The platform generates its own public XML response at a route such as /rss/{podcastSlug}.xml. No external RSS-generation API is required. The service reads the podcast channel and eligible published episodes, creates valid XML, caches it briefly, and returns Content-Type: application/rss+xml.

11. Module 4 - Thumbnail Generator with AI Text Overlay
Purpose and design strategy
Generate a strong thumbnail concept and accurate editable text without depending on an image model to spell the final headline. AI proposes hooks and visual direction; the user selects an uploaded or stock background; Konva.js/Fabric.js renders text, logo, shapes, gradients, and effects in the browser.
Workflow
1. Enter video title, audience, category, emotion, and brand settings.
2. Generate 3-5 short headline options and stock-image search terms.
3. Search Unsplash or upload an image; choose the target aspect ratio.
4. Edit layers: headline, subtext, logo, subject image, shapes, gradient, outline, and shadow.
5. Save canvas JSON for future edits and export PNG/JPG.
Functional requirements
ID
Requirement
TH-01
Support 16:9, 9:16, and 1:1 presets with safe-area guidance.
TH-02
Support drag, resize, rotate, align, layer order, undo, and redo.
TH-03
Generate headline, visual concept, text-position, and search-keyword suggestions.
TH-04
Allow stock images, user uploads, logo uploads, and reusable brand presets.
TH-05
Store editable canvas JSON separately from the final exported image.
TH-06
Export correct pixel dimensions and warn about low-resolution source images.
Free API recommendation
Gemini + Unsplash + Konva.js
This is the most dependable no-cost MVP path. AI-generated backgrounds may be offered as a limited experimental option, but the product must remain fully usable without them. Follow Unsplash attribution and usage requirements.

14. Module 5 - Reference Images, Exports, and Acceptance
Reference image strategy
For a reliable free workflow, Gemini generates a stock-search query for each scene and Unsplash provides candidate reference images. Users may upload product and lifestyle images. Optional AI-generated images must be rate-limited, cached, and clearly identified as references rather than production-ready final frames.
Consistency controls
Store reusable character description, wardrobe, product packaging, brand colors, and visual style.
Keep generated background and real product image as separate layers where possible.
Allow a user to lock the visual reference for approved scenes.
Warn that generated references may contain visual inconsistencies and require human review.

Acceptance scenario
Module 5 acceptance
A user enters a 30-second vertical product-sale brief, receives three concepts, selects one, generates 5-8 timed scenes, locks the hook, regenerates other scenes, replaces a reference image, fixes a duration overrun, and exports a readable storyboard PDF plus shot list.
Free API recommendation
Gemini Flash for structured concepts/scenes; Unsplash and user uploads for reference imagery; Konva.js for optional overlays; jsPDF, pdf-lib, or server-side PDF generation for exports. The backend validates every generated JSON response before saving.

Podcast directories fetch the platform RSS URL; automatic submission integrations are later scope.
AI-generated reference images are optional and not required for core product acceptance.
